# EasyWeek API probe — операторский runbook (PR-2)

Read-only проба публичного API EasyWeek v2. Единственная цель — до того, как на
них завяжутся схема (PR-3) и нормализатор (PR-4), убедиться живьём, что:

1. API-ключ и workspace slug приняты (`GET /ping`);
2. видно, **какие локации** доступны этому ключу (`GET /locations`);
3. какие UUID соответствуют филиалам — чтобы оператор собрал `EASYWEEK_LOCATION_MAP`;
4. опционально — что конкретная запись читается (`GET /bookings/{uuid}`).

Проба **не может ничего изменить**: клиент GET-only, mutation-методов нет
(INTEGRATION_PLAN §1.6 п.8). Один API-ключ видит несколько локаций, поэтому
numeric `location_id` из вебхука UUID **не заменяет** (§1.6 п.5).

---

## 1. Конфигурация

Секреты EasyWeek живут в отдельном `easyweek.env` рядом с `.env` (gitignored,
`required: false` — без файла сервис поднимается).

```bash
cp easyweek.env.example easyweek.env
```

Заполните два значения (ключ берётся в EasyWeek: **Settings → Developers → API
keys**):

```text
EASYWEEK_API_KEY=<Bearer key>
EASYWEEK_WORKSPACE_SLUG=<slug воркспейса>
```

`EASYWEEK_API_BASE_URL` уже задан по умолчанию и менять его не нужно: клиент
принимает **только** канонический origin `https://my.easyweek.io/api/public/v2`
и отвергает всё остальное (другой хост, `http://`, другой путь, порт, query) —
иначе Bearer-ключ мог бы уйти открытым текстом или на чужой сервер.
`EASYWEEK_LOCATION_MAP` пока оставьте `{}` — записи филиалов добавляются только
после этой пробы.

⚠️ **Уже работающий контейнер не перечитывает `easyweek.env` сам.** После любой
правки файла (и перед первым probe) обязательно пересоздайте сервис:

```bash
docker compose up -d --force-recreate altegio-api
```

Обычного `restart` и `docker compose up -d altegio-api` **без** `--force-recreate`
недостаточно: контейнер продолжит работать со старым окружением, и probe
покажет устаревший результат — например «нет ключа» сразу после того, как вы
его вписали.

Отсутствие `easyweek.env` не ломает ни импорт приложения, ни API-контейнер, ни
Altegio-воркеры: без ключа падает только сама проба, с понятным кодом выхода.

## 2. Запуск

Локально:

```bash
uv run python -m altegio_bot.scripts.easyweek_probe --redact-pii
```

На проде — строго в этом порядке:

```bash
nano easyweek.env
```

```bash
docker compose up -d --force-recreate altegio-api
```

```bash
docker compose exec -T altegio-api \
  /app/.venv/bin/python \
  -m altegio_bot.scripts.easyweek_probe \
  --redact-pii
```

Коды выхода:

| Код | Значение |
|---|---|
| `0` | проба прошла |
| `2` | ошибка конфигурации (нет ключа/slug/битый base URL) |
| `3` | ошибка API или протокола (401/403/404/422, 429/5xx после ретраев, не-JSON ответ) |

`--redact-pii` включён **всегда**; флаг оставлен только для явности. Небезопасного
режима в PR-2 нет намеренно. Вывод строится по **allowlist**, а не попыткой
замаскировать сырой ответ: новое или переименованное поле на стороне EasyWeek не
может утечь по умолчанию. `customer`, телефон, e-mail, имя, notes/comments,
суммы заказа, заголовки, сырое тело и Bearer-ключ не печатаются никогда.

Sanitized пример успешного вывода (stdout — только этот JSON, логи идут в stderr):

```json
{
  "locations": {
    "count": 1,
    "items": [
      {
        "address": { "address_1": "Beispielstr. 1", "apt": null, "city": "Musterstadt", "postal_code": "00000" },
        "name": "Durlach",
        "timezone": "Europe/Berlin",
        "uuid": "00000000-0000-0000-0000-000000000000"
      }
    ]
  },
  "ok": true,
  "ping": { "ok": true, "version": "v12.32.3" }
}
```

### 2.1. Форма ответа `GET /locations`

Живой API возвращает `timezone` **объектом**, а не строкой:

```json
{ "timezone": { "name": "Europe/Berlin", "offset": "+02:00", "short": "CEST" } }
```

Клиент принимает обе формы: строку и объект. Обязателен только непустой
`timezone.name`; `offset` и `short` могут отсутствовать, быть `null` или
измениться на стороне EasyWeek — проба из-за этого не падает. Если пригодного
`timezone.name` нет, вся выдача `list_locations()` завершается
`EasyWeekProtocolError`: неполный список показывать оператору нельзя, иначе UUID
будет выбран по частичным данным.

Проба печатает timezone **только строкой** — IANA-именем:

```json
{ "timezone": "Europe/Berlin" }
```

`offset` и `short` в вывод не попадают: для опознания филиала они не нужны и
только расширяют поверхность вывода.

Адресные поля живого API называются иначе, чем в документированном примере: это
`address_1`, `apt`, `city`, `postal_code`. Проба поддерживает и их, и прежние
`country`, `city`, `street`, `house`, `zip_code`, и печатает каждое **под
исходным именем** — переименование `address_1 → street` было бы доменной
нормализацией и относится к PR-4.

`position` (вложенный объект, может содержать координаты) намеренно **не
выводится**, как и `description`, `images`, `opening_hours`, `is_address_hidden`,
а также пагинационные `links` и `meta`. Список полей — allowlist: новое поле на
стороне EasyWeek не появится в выводе без явной правки кода.

Пример ошибки — только безопасные метаданные, без тела ответа:

```json
{
  "attempts": 1,
  "error": "EasyWeekAuthError",
  "ok": false,
  "operation": "ping",
  "retryable": false,
  "status": 401
}
```

## 3. Фиксация реестра филиалов

1. Найдите Дурлах в `locations.items`.
2. Сверьте **name**, **timezone** (ожидается строка `Europe/Berlin`) и адрес
   (`address_1`/`city`/`postal_code` либо legacy-поля) — один ключ видит
   несколько локаций, поэтому выбор делается глазами, а не «первым в списке».
3. Впишите подтверждённые UUID вместе с numeric id, Meta-префиксом и страницей
   записи в **production** `easyweek.env`:

   ```text
   EASYWEEK_LOCATION_MAP=<JSON-реестр подтверждённых филиалов>
   ```

4. Пересоздайте контейнер, чтобы значение подхватилось (снова **именно**
   `--force-recreate`, не `restart`):

   ```bash
   docker compose up -d --force-recreate altegio-api
   ```

5. **Не коммитьте** ни UUID вместе с ключом, ни сам `easyweek.env`, ни другие
   production-секреты. В задачу/тикет прикладывайте только sanitized вывод пробы.

## 4. Опционально: проверка чтения записи

Если нужно убедиться, что чтение брони работает (например, по UUID из
захваченного PR-1 вебхука):

```bash
docker compose exec -T altegio-api \
  /app/.venv/bin/python \
  -m altegio_bot.scripts.easyweek_probe \
  --booking-uuid <booking uuid>
```

Выводятся только: `uuid`, `location_uuid`, start/end (UTC и локальные),
`timezone`, `status_type`, `is_canceled`, `is_completed` и агрегат по услугам
(количество + названия). `customer`, notes/comments и суммы заказа не выводятся.

Невалидный UUID отклоняется **до** HTTP-запроса (код выхода `3`), поэтому
пробой нельзя случайно обратиться к произвольному пути.

## 5. Поведение при сбоях

Клиент повторяет запрос максимум **3 раза** и только для тех классов, где повтор
осмыслен: `429`, `5xx`, timeout и сетевые/транспортные ошибки. Backoff
экспоненциальный с jitter и потолком; `Retry-After` учитывается, но обрезается
сверху (10 с), чтобы враждебное или ошибочное значение не подвесило пробу.

Повторяется **весь** диапазон `5xx`, а не отдельные коды: любой серверный статус
(включая `505`, `507`, `599` или собственную ошибку прокси) — это проблема на той
стороне, и считать его постоянным значило бы потерять восстановимый запрос.

Не повторяются: `400`, `401`, `403`, `404`, `422`, прочие постоянные `4xx` и
успешный ответ с некорректным телом — повтор не может изменить результат.

Проба намеренно строгая к «успешным» ответам: `200` сам по себе ничего не
доказывает (так может ответить прокси или каптив-портал). Пробa завершится с
кодом `3`, если:

* `/ping` не вернул документированный признак `{"ping": "pong"}`;
* список локаций пришёл не списком, без ключа `data` или с элементом-не-объектом
  (битые элементы **не** отбрасываются молча — иначе вы выбрали бы UUID из
  неполного списка);
* локаций не видно вообще — тогда зафиксировать UUID Дурлаха невозможно, и это
  провал пробы, а не успех с пустым результатом;
* у брони в ответе есть ключ `data`, но он не объект, либо нет пригодного `uuid`.

Лимит EasyWeek — 60 запросов в минуту на ключ; проба делает 2–3 запроса, так что
её можно спокойно запускать повторно.
